   the pre-quoted FQN as `table_duckdb_path`; the profiler re-quotes → DuckDB
   `zero-length delimited identifier` → every enriched join-column profile failed

   skip).
3. **`temporal_drift` wrote 0 records ever** — session detect carries the SESSION
   run's run_id; semantic/statistics rows are written by the ADD_SOURCE run, so
   strict this-run loader reads found nothing and `can_run` silently failed.
   **FIXED** (loaders fall back to the promoted `MetadataSnapshotHead` run).
   Recall now 0.933–1.000 on the injected 1.35× shift.
4. **`slice_variance` over-fired on clean data** (1.000 on `payment_id`,
   `entry_id`, …) — same root cause as 3: the missing semantic read disabled its
   `_SKIP_ROLES` gate (fail-open). **FIXED** by the same loader fallback; role
   gate verified (41→11 records).
5. **Network edges too weak to ever band** — `temporal_drift→query_intent` 0.3
   meant even a maximal score rolled to ≤ the 0.3 clean-band floor;
   `relationship_quality→reporting_intent` 0.5 couldn't band the sqrt-boosted
   20%-orphan fixture (0.447). **CALIBRATED** to 0.45 / 0.75.

## Decisions (Philipp, 2026-06-05)

- **Hybrid on clean scores**: slice_variance's clean scores are accurate
  heterogeneity (cost_center is 52% null with sharp per-slice spread →
  aggregation `blocked` is honest) — accepted into regenerated baselines.
  temporal_drift on periodic snapshots is a false-positive class → gate on
  `temporal_behavior == 'point_in_time'`. Long-term classifier for
  expected-vs-problem patterns: business-pattern filter (**DAT-184**; DAT-186's
  slice_variance suppression was deduped into it).
- **Relationship problems live at relationship grain** (DAT-408 model): eval
  floors assert the `relationship:` target's band (indexed per endpoint), the
  endpoint column's own band stays blind to them by design.
- derived_value readiness floor follows formula ATTRIBUTION (score lands on
  `journal_lines.debit` — the dedup-preferred sum form — not the injected
  `net_amount`), mirroring the recall test's `_find_score`.

## Still open (engine follow-ups)

6. **Semantic concept matching ignores exact indicator matches.** `debit_balance`
   exactly matches the new `account_balance` concept's indicators (added this
   session, `verticals/finance/ontology.yaml`), yet a live run still grounds it
   to the `debit` FLOW concept (additive). Consequence: `temporal_behavior` is
   unreliable → temporal_drift's point-in-time gate is inert on trial_balance →
   clean TB drift entries (0.447/0.535, seed-stable) live in the clean baseline
   until fixed. Proposed: deterministic exact-indicator override in the semantic
   phase. Candidate new ticket.
7. **Stale slice definitions are systemic** — `SliceDefinition` rows +
   `sql_template`s are table-scoped and immortal with no run/head scoping;
   `slicing` skips itself when definitions exist; views are run-versioned and
   LLM-shaped. Three manifestations in one day (begin_session hard-fail,
   period-slice profiling warnings, `drift_analysis_failed` GROUP BY). DAT-422
   content-keying makes the leakage CROSS-strategy (same bytes → same table_id).
   Eval works around it by wiping PG between baselines; cockpit teach re-runs
   hit it for real. Proposed: run-version definitions via `MetadataSnapshotHead`,
   re-derive instead of skip on column-set change. Candidate new ticket.
8. **Coverage gaps (testdata):** `slice_variance` has no recall injection
   (precision-only coverage); `derived_value` exercises exactly 1 formula.
   The DAT-403 handoff's value-layer injection hints remain open.
